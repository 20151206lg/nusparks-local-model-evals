X1 DEFECT (blocker) A process that has handled a request with a hung partner cannot exit. `python3 -c "from rtb.models import BidRequest; from rtb.partners import MockPartner; from rtb.exchange import run_request; import time; run_request(BidRequest.from_json({'id':'r','tmax':100,'imp':[{'id':'1','bidfloor':0.1}]}), [MockPartner('a',1.0,6000)], time.monotonic())"` returns in about 100 ms but the process then keeps running for about 6 s (a non-daemon ThreadPoolExecutor worker is still sleeping). With a partner that never returns it never exits. Required design: no ThreadPoolExecutor. For each (partner, impression) call start one `threading.Thread(daemon=True)`; each thread puts (arrival counter, partner name, bid) on a per-request `queue.Queue`; the request reads the queue with `timeout=remaining` until the single shared deadline and ignores everything that arrives later. All state is per request. A partner that never answers must not delay the response or the process exit.

X2 DEFECT The response seat is the constant "exchange" (exchange.py, `responses.setdefault("exchange", [])`). Rule: seat = the name of the partner that placed the winning bid; one SeatBid per partner that won at least one impression. Take the name from the partner object that produced the bid (the X1 queue entry carries it), not from the bid id.

X3 DEFECT Tie-break "if still tied, the partner that answered first wins" uses list order, not arrival order. Two open bids at the same price from partners listed [slow, fast], where fast answers at 5 ms and slow at 40 ms (tmax 100): the winner must be fast; today it is slow. Use the arrival counter from X1.
